# Vocabulary

This file defines the domain concepts used across the spec. The interface designer
turns them into Rust types. Identifiers are opaque newtypes unless stated otherwise.
Handbook terms (tier, trust zone, stage, stage graph, oracle, discipline pack) are used
as defined in [brightsmiths/handbook](https://github.com/brightsmiths/handbook)
`docs/` **[EXT]** and are not redefined here.

## Core concepts

### Attempt
- **What it is:** one execution of one stage (or one gate check) in one fresh VM. This is the unit of
  isolation, budgeting, telemetry and teardown.
- **Identifier:** `AttemptId`. A ULID, generated by the runner at acceptance. It is unique, sortable and
  never reused.
- **Fields:** request, current `AttemptState`, timestamps per state, `AttemptResult` once terminal.
- **Lifespan:** from request acceptance until the result is returned and teardown is confirmed.
  Nothing of an attempt survives teardown except the result and the exported telemetry.

### AttemptRequest
- **What it is:** the caller's full, immutable description of what to run.
- **Fields:**
  - `caller`
  - `run_key`
  - `stage`
  - `idempotency_key`
  - `image`
  - `repository`
  - `checkout_sha`
  - `context_bundle`
  - `mount_plan` (a reference or an inline value)
  - `network_profile`
  - `limits`
  - `identity_role`
  - `output_schema`
  - `output_record_mode`
  - `stage_branch` (required when the caller is CogWorks, forbidden when it is gate-warden)
  - `oracle_manifest_signing` flag
- **Constraints:**
  - The request is validated against [`attempt-request.schema.json`](../schemas/attempt-request.schema.json)
    before anything is provisioned.
  - The request carries no secrets.
- **Schema:** [`../schemas/attempt-request.schema.json`](../schemas/attempt-request.schema.json).

### AttemptResult
- **What it is:** the runner's account of what happened. It is returned to the caller and is the basis of the
  GitHub output record.
- **Fields:**
  - `attempt_id`
  - `outcome` (`AttemptOutcome`)
  - `reason` (`ReasonCode` + detail)
  - pushed commit SHAs and branch
  - output record, or a reference to it
  - dispute record
  - scope verdict
  - resource usage vs limits
  - phase timings
  - telemetry references
  - teardown confirmation
- **Constraints:** it never contains a pass/fail verdict on the work itself. Only gate-warden decides that.
- **Schema:** [`../schemas/attempt-result.schema.json`](../schemas/attempt-result.schema.json).

### AttemptOutcome
- **What it is:** the closed set of terminal states.
- **Values:**
  - `published`: commits pushed and output record written.
  - `completed`: gate-warden mode. Results returned, nothing pushed.
  - `rejected`: the runner refused the produced work, for example on a scope violation, an invalid
    output or a forbidden commit content.
  - `failed`: an infrastructure or agent failure, for example a budget exceeded, a provider error or a push
    failure.
  - `invalid_request`: refused before provisioning.
- **Constraints:** none of these values means "pass" or "fail" for the work itself.

### AttemptState
- **What it is:** a lifecycle state.
- **Values:** `Requested → Validated → Provisioned → Running → Collected → ScopeChecked →
  Publishing → (terminal outcome) → Destroyed`. See [architecture.md](architecture.md).
- **Constraints:** every state, including failure states, eventually reaches `Destroyed`.

### Caller
- **What it is:** the component that sent the request.
- **Values:** `cogworks` or `gate-warden`. The caller selects the mode:
  - `cogworks`: the runner pushes and writes the output record.
  - `gate-warden`: the runner returns results only. It does not push and does not post checks.

### RunKey
- **What it is:** the CogWorks run identifier, or the gate-warden check-run identifier.
- **Identifier:** an opaque string supplied by the caller.
- **Use:**
  - The model gateway keys token and turn budgets on it.
  - Telemetry correlation uses it.
  - It appears in GitHub records.

### Stage
- **What it is:** the name of the stage (or gate) in the caller's stage graph, for example `implement` or `G3`.
- **Constraints:** the runner treats it as an opaque label used for routing, telemetry and naming. It has no
  behavioural meaning to the runner.

### Image
- **What it is:** the VM root filesystem image.
- **Fields:** an OCI reference that **must be pinned by digest** (`sha256:`).
- **Constraints:**
  - It contains task-marshal and the agent CLI.
  - It is mounted read-only.
  - A tag alone is rejected.

### Provider / Sandbox
- **Provider:** a microVM backend behind the `SandboxProvider` trait. L1 has `microsandbox` (libkrun). L2
  adds `firecracker` or `kata`.
- **Sandbox:** a provider-specific instance. It is owned by exactly one attempt.

### Workspace
- **What it is:** the per-attempt host directory tree that is presented to the VM, holding the checkout at
  `checkout_sha`, the context bundle and the output area.
- **Lifespan:** it is created at provisioning and deleted at teardown, and is never shared.

### MountPlan / MountEntry
- **What it is:** agent-gate's decision about which paths the role may see and write.
- **Fields:** an ordered list of `MountEntry` values, each holding:
  - `path`: a normalised, workspace-relative path.
  - `access`: `read_write`, `read_only` or `absent`.
  - `owner`: uid/gid inside the VM.
  - A default access level for paths the plan does not match.
- **Constraints:**
  - Paths are normalised. `..`, absolute paths and NUL characters are rejected.
  - When entries overlap, the most specific path wins.
  - The default must be `absent` or `read_only`.
  - The runner never widens the plan.

### ContextBundle
- **What it is:** the read-only context CogWorks built for the stage.
- **Fields:** a content-addressed reference (digest) and a size.
- **Constraints:**
  - It is presented as a read-only mount.
  - Its size is capped by configuration (default 256 MiB **[EXTRAP]**).
  - If the digest does not match, the attempt is rejected.

### NetworkProfile / EgressAllowlist
- **NetworkProfile:** a named, versioned set of `EgressRule`s. Each rule holds:
  - `destination_kind`: `model_gateway`, `package_registry` (with an `ecosystem` such as `crates`, later
    `npm`, `pypi` or `oci`), or `declared_extra`.
  - `endpoint`
  - `credential_ref`: a reference only, never a value.
- **EgressAllowlist:** the effective set of rules for an attempt. It is the profile plus any extras declared
  in the stage contract.
- **Constraints:** anything not in the allowlist is denied. See [egress.md](egress.md).

### ResourceLimits
- **What it is:** the caller-supplied budget for the attempt.
- **Fields:** `vcpus`, `memory_mib`, `wall_clock_seconds`, plus optional `disk_mib` and `output_max_bytes`.
- **Constraints:**
  - Each value is bounded by host configuration maximums.
  - The runner enforces them from outside the VM.

### IdentityRole
- **What it is:** the stage's identity role, for example `oracle`, `builder`, `designer` or `reviewer`.
- **What it selects:**
  - which GitHub App installation token is used for the push;
  - which signing key, if any, may be used;
  - the uid inside the VM.
- **Constraints:** it maps to the handbook trust zones **[EXT]**.

### OutputSchemaRef / OutputRecord
- **OutputSchemaRef:** where the JSON Schema for the stage's output record lives. It is a path at a pinned
  revision in the harness repository, or a digest.
- **OutputRecord:** the agent's structured result, written by `task-marshal done`. It is validated by the
  runner, outside the VM, against the schema.
- **OutputRecordMode:** `comment` (the runner posts a signed comment on the stage's issue or PR) or
  `committed_file` (the record is a file in the pushed commits at a path given by the stage contract). The
  stage contract chooses the mode.

### DisputeRecord
- **What it is:** a structured objection raised by the agent through task-marshal, for example "the locked
  test is wrong". It is optional.
- **Constraints:** it is collected and published alongside, or instead of, the output record. The runner never
  interprets it.

### CommitBundle
- **What it is:** a git bundle produced from the VM workspace that contains the commits between
  `checkout_sha` and the head of the agent's work branch. It is the **only** supported way to hand work back
  in L1. Patches are not supported (see
  [ADR-0006](../adr/ADR-0006-commit-bundle-handoff.md)).
- **Constraints:**
  - The commits must descend from `checkout_sha`, and there must be no merge commits from unknown
    history.
  - The bundle has a size cap.
  - The runner re-reads it on the host. Nothing from it is executed.

### ScopeVerdict
- **What it is:** agent-gate's result for the commit range `checkout_sha..head` under the role and mount plan.
- **Values:** `in_scope`, or `out_of_scope` with a list of violating paths.

### StageBranch
- **What it is:** the target branch that the runner pushes to. It is supplied by CogWorks.
- **Constraints:**
  - It must match the configured stage-branch pattern **[EXTRAP]**, for example
    `factory/<run>/<stage>`.
  - It is never the default branch and never a protected branch.

### RoleToken
- **What it is:** a minutes-lived GitHub App installation token for the role. It is scoped to the single
  repository with the minimal permissions needed.
- **Lifespan:** it is fetched just before the push and dropped right after. It exists only in host memory.
- **Constraints:** it is a secret type. It implements no `Debug` or `Display` and is never logged or
  serialised.

### OracleManifest / ManifestSignature
- **OracleManifest:** the manifest of locked oracle files. oracle-guard computes it inside the VM.
- **ManifestSignature:** a signature made by the runner on the host with the oracle role key, held in the KMS,
  and only after the runner has recomputed the manifest digests from the collected commits and found that
  they match.

### TelemetryStream
- **What it is:** the in-VM telemetry streamed to the host over a host-owned channel: process output, process
  events, task-marshal events and resource samples. See [observability.md](observability.md).
- **Constraints:** it is untrusted data. It is size-limited and rate-limited, and it is tagged by the host.

### CorrelationContext
- **Fields:** `attempt_id`, `run_key`, `stage`, `caller`, `repository`, `checkout_sha`, and the trace ID.
- **Where it goes:** it is attached to every span, log line, proxy request (as headers to the gateway) and
  GitHub record.

## Error concepts (ReasonCode)

Each terminal non-success outcome carries exactly one primary `ReasonCode`.

| ReasonCode | Outcome | Meaning | Retryable by caller | Security note |
| --- | --- | --- | --- | --- |
| `request_invalid` | invalid_request | Schema or semantic validation failed | No (fix request) | Detail must not echo untrusted content verbatim |
| `image_not_pinned` | invalid_request | Image not referenced by digest | No | Prevents image substitution |
| `mount_plan_invalid` | invalid_request | Plan unparsable, non-normalised paths, or unsafe default | No | |
| `context_bundle_invalid` | invalid_request | Digest mismatch or over size cap | No | |
| `provider_unavailable` | failed | No capacity or provider error before start | Yes | |
| `checkout_failed` | failed | SHA not found or fetch failed | Maybe | |
| `budget_wall_clock` / `budget_memory` / `budget_cpu` | failed | Limit exceeded; VM killed | Caller decides | |
| `agent_exit_nonzero` | failed | Agent process failed without a dispute record | Caller decides | |
| `no_commits` | rejected | Stage required commits; none produced | Caller decides | |
| `bundle_invalid` | rejected | Bundle unreadable, oversize, wrong ancestry, or forbidden objects | No | Possible tampering |
| `output_invalid` | rejected | Output record missing or fails schema | Caller decides | |
| `scope_violation` | rejected | agent-gate reports out-of-scope paths | No | Possible attack; logged at warn |
| `scope_check_unavailable` | failed | agent-gate unreachable; fail closed | Yes | |
| `manifest_mismatch` | rejected | Recomputed oracle manifest differs from in-VM manifest | No | Possible tampering |
| `token_unavailable` | failed | KMS / App could not issue role token | Yes | |
| `push_failed` | failed | Push rejected (non-fast-forward, protected) or network | Maybe | |
| `record_publish_failed` | failed | Push succeeded but output record could not be written | Yes (idempotent) | |
| `teardown_failed` | (annotation) | Destruction not confirmed; host quarantined | n/a | Raises an alert |
